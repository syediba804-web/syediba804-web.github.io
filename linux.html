Linux / CLI: Beginner to Intermediate

Get comfortable in the terminal: move around, manage files, search, chain commands, handle permissions and processes, and write small shell scripts.

10 topics10-question quiz8 assignments

1. Terminal basics Beginner

The terminal lets you control the computer by typing commands. The shell (usually Bash or Zsh) reads and runs them. Linux is the family of operating systems behind most servers, and macOS and Windows (via WSL) offer similar shells.

whoami          # your username
pwd             # where am I? (print working directory)
date            # current date and time
clear           # clean the screen (or Ctrl+L)
man ls          # manual for a command (q to quit)
ls --help       # quick help
Time saversPress Tab to auto-complete names, ↑ for previous commands, Ctrl+C to stop a running command, and history to see past commands.

Command anatomy: command -options arguments, e.g. ls -l /home.

2. Navigating the file system Beginner

Everything starts at the root /. Your home folder is ~.

PathMeaning
/root of the whole system
~your home directory
.current directory
..parent directory
/etc, /var, /usr, /homeconfig, logs/data, programs, users
ls              # list files
ls -l           # long format (permissions, size, date)
ls -a           # include hidden files (start with .)
ls -lh          # human-readable sizes
cd projects     # go into a folder
cd ..           # go up one level
cd ~            # go home (just "cd" works too)
cd -            # go back to the previous folder
tree            # show folders as a tree (if installed)

Absolute paths start with / (/home/ibraheem/notes). Relative paths start from where you are (notes/python).

3. Creating, copying and deleting Beginner

mkdir projects            # new folder
mkdir -p a/b/c            # create nested folders
touch notes.txt           # new empty file
cp notes.txt backup.txt   # copy a file
cp -r folder folder2      # copy a folder (recursive)
mv notes.txt docs/        # move
mv old.txt new.txt        # rename
rm notes.txt              # delete a file
rm -r folder              # delete a folder and its contents
rmdir empty_folder        # delete an empty folder
No recycle bin!rm deletes permanently. Double-check before running it, and never run rm -rf with a path you aren't 100% sure about. Use rm -i to be asked for confirmation.

Viewing files

cat file.txt          # print the whole file
less file.txt         # scroll through (q to quit)
head -n 5 file.txt    # first 5 lines
tail -n 5 file.txt    # last 5 lines
tail -f app.log       # follow a log live
wc -l file.txt        # count lines (-w words, -c bytes)
nano file.txt         # simple text editor (Ctrl+O save, Ctrl+X exit)

4. Searching with find and grep Beginner Intermediate

find . -name "*.py"                 # files ending in .py under current folder
find . -type d -name "node_modules" # folders only
find . -size +10M                   # files bigger than 10 MB

grep "error" app.log                # lines containing "error"
grep -i "error" app.log             # ignore case
grep -n "TODO" *.py                 # show line numbers
grep -r "def main" .                # search in all files recursively
grep -v "debug" app.log             # lines NOT containing debug
grep -c "error" app.log             # count matching lines

Wildcards: * matches anything, ? one character, [abc] one of a, b, c. Example: ls *.txt.

5. Pipes and redirection Intermediate

Small tools become powerful when chained together.

SymbolMeaningExample
|send output to next commandls | wc -l
>write output to a file (overwrite)ls > files.txt
>>append to a fileecho hi >> log.txt
<read input from a filesort < names.txt
2>redirect errorscmd 2> errors.txt
&&run next only if previous succeededmkdir x && cd x
cat names.txt | sort | uniq -c | sort -nr | head -5    # top 5 most frequent lines
history | grep git                                    # find old git commands
ls -l | grep ".py" | wc -l                            # how many Python files?
echo "Hello" > hello.txt                              # create a file with text
cut -d"," -f1 data.csv | sort -u                      # unique values of first CSV column

6. Permissions and users Intermediate

Run ls -l and you'll see something like:

-rwxr-xr--  1 ibraheem staff  1024 Oct 24 notes.sh
 ↑↑↑↑↑↑↑↑↑
 │└┬┘└┬┘└┬┘
 │ │  │  └── others: r-- (read only)
 │ │  └───── group:  r-x (read, execute)
 │ └──────── owner:  rwx (read, write, execute)
 └────────── type: - file, d directory
LetterNumberMeaning
r4read
w2write
x1execute
chmod +x script.sh        # make executable
chmod 755 script.sh       # owner rwx (7), group r-x (5), others r-x (5)
chmod 644 notes.txt       # owner rw-, others read only
chown user:group file     # change owner (needs sudo)
sudo apt update           # run as administrator (Debian/Ubuntu)
Careful with sudoIt bypasses safety checks. Only use it when you understand the command.

7. Processes and system info Intermediate

ps aux                 # list all processes
top                    # live view (q to quit)
kill 1234              # ask process 1234 to stop
kill -9 1234           # force stop
sleep 60 &             # run in the background
jobs                   # background jobs
df -h                  # disk space

free -h                # memory usage
uname -a               # system information

Ctrl+C stops a program, Ctrl+Z pauses it, fg resumes it in the foreground.

9. Shell scripting basics Intermediate

A script is a file of commands. Create hello.sh:

#!/bin/bash
# greet.sh: a small example script

name=${1:-friend}            # first argument, default "friend"
echo "Hello, $name!"

if [ -d "projects" ]; then
  echo "projects folder exists"
else
  mkdir projects
  echo "created projects folder"
fi

for file in *.txt; do
  echo "Found: $file"
done

count=$(ls | wc -l)
echo "This folder has $count items"
chmod +x greet.sh
./greet.sh Ibraheem

Useful test flags

-f file exists, -d directory exists, -z string is empty, -eq numbers equal, -lt less than, -gt greater than.

TipQuote your variables ("$name") so spaces don't break your script, and use set -e to stop on the first error.
